# NS-SIM

警備・災害対応シミュレーションゲーム（試作版）。
React + TypeScript + Vite 製のレスポンシブ Web アプリで、MacBook・iPad・iPhone のブラウザで動作します。

## シナリオ 01：商業施設 自動火災報知設備 発報

架空の商業施設「NSショッピングプラザ」の防災センター指令担当として、警備員3名に指示を出し、火災報知設備の発報に対応します。

| 区域 | 階 | 名称 |
| --- | --- | --- |
| A | 1F | 正面エントランス |
| B | 1F | フードコート |
| C | 2F | 物販エリア |
| D | 2F | 倉庫・バックヤード（発報区域） |
| E | 3F | シネマ |
| F | B1F | 駐車場 |

- **警備員**：警備1 田中（隊長・防災センター）、警備2 佐藤（1F 巡回）、警備3 鈴木（B1F 巡回）
- **指示**：現場確認 / 初期消火 / 避難誘導 / 防災センターへ帰隊 / 待機
- **防災センター指令**：119番通報 / 非常放送（全館避難）
- **時間経過**：×1・×2・×4 の速度切替と一時停止。移動時間は階差で変化し、放置すると火勢が拡大して隣接区域へ煙が流入します
- **時系列ログ**：発報・指令・報告・危険・完了をすべて時刻付きで記録
- **評価（After Action Review）**：鎮火または延焼拡大で状況終了となり、記録されたイベント履歴から100点満点で評価（下記）

## 評価システム（After Action Review）

状況終了時に、ゲーム中に記録された構造化イベント（`GameState.events`）だけを入力として採点します。評価は `src/evaluation/` の純粋関数で、同じ履歴からは常に同じ結果になります。

> 評価基準は NS-SIM の訓練用に定めた**架空の基準**です。消防法令・実在施設の消防計画・警備業務の運用基準を示すものではありません。

| 項目 | 配点 | ルール |
| --- | --- | --- |
| 安全管理 | 30 | S1 在館者の避難開始（10）/ S2 煙曝露の抑制（8）/ S3 警備員の安全確保（12） |
| 初動対応 | 25 | F1 発報区域への派遣指示（10）/ F2 119番通報（10）/ F3 発報区域からの第一報告（5） |
| 指揮統制 | 20 | C1 役割分担（8）/ C2 指示の一貫性（6）/ C3 待機隊員の活用（6） |
| 情報管理 | 15 | I1 状況変化への対応（6）/ I2 情報に基づく派遣先（5）/ I3 火災の現場確認（4） |
| 事態収束 | 10 | R1 火災の鎮圧（6）/ R2 終了時の在館者の安全（4） |

- **ランク**：S 90〜 / A 80〜 / B 70〜 / C 60〜 / D 〜59。重大な安全違反（V1 退避判断後の火災区域への進入指示、V2 避難措置の重大な遅れ、V3 119番通報の重大な遅れ・火災確認後の通報未実施）があれば上限 C
- **時間の基準**：派遣は第1報から、避難は「火災判断時点」（火災確認・煙確認・第2報のうち最も早い情報）から計測
- **119番通報（F2）**：隊員による火災確認から通報までを評価（60秒以内 10点 / 120秒以内 6点 / 240秒以内 3点 / それ以降の通報 1点 / 未実施 0点、確認前の通報は満点）。初期消火とは独立して評価し、初期消火に成功して状況が終わっても、確認から終了まで30秒以上あれば通報未実施として評価する。火災が確認されていない場合は通報の有無だけで減点しない。これらの秒数は NS-SIM 独自の訓練基準で、消防法令上の義務を判定するものではない
- **判定不能・対象外**：期限前に状況が終わった項目や記録不足の項目は、成功・失敗のどちらにもせず配点から除外し、判定できた配点で100点満点に換算して画面に明示。開始・終了の記録がない、または判定できた配点が60点未満の場合、ランクは判定保留
- **評価根拠**：各判定にイベント ID・時刻を付けて表示
- **履歴**：評価結果のみをブラウザの localStorage（`ns-sim:aar-history:v1`）に直近20件保存。保存できない場合は警告を表示

## v0.3：ランダム生成シナリオ（難易度選択）

開始画面で「ランダム生成（v0.3）」を選ぶと、難易度とシードに応じて施設と事案を生成します。シナリオ01（従来版）は別モードとしてそのまま残っており、動作と評価（`scenario-01/1.1.0`）は v0.2.1 から変わりません（`src/game/classic.golden.test.ts` で固定値と照合）。

| 難易度 | 施設 | 警備員 | 事案 | 評価方式 |
| --- | --- | --- | --- | --- |
| Easy | 2〜3フロア・4〜6区域 | 3名 | 1件（事前告知） | 適応型 |
| Normal | 3〜4フロア・6〜9区域 | 4名 | 1〜2件 | 適応型 |
| Hard | 4〜5フロア・9〜12区域 | 5名 | 2〜3件（同時発生・地震あり） | 適応型 |
| Expert | 5〜6フロア・12〜16区域 | 6名 | 非公開（通常勤務から開始、誤報・区域の取り違えあり） | ハイブリッド型 |

- **事案**：火災（煙は隣接区域へ拡大、初期消火・119番（火災）・避難）、地震（揺れの間は隊員が身の安全を確保、収束後に全区域の安全確認）、傷病者（容体が悪化、救護・119番（救急）・救急隊への引継ぎ）。種別ごとのアイコン・発生時の強調表示・状況ボードで表示
- **Expert の不確かな情報**：感知器の誤作動（非火災報）は現場確認まで本物の火災と区別できない。傷病者の通報は区域を取り違えることがあり、現場に着くと正しい区域が判明する
- **再現性**：同じ難易度・シードからは同じ施設・事案を生成（シード入力欄で指定可）。生成時に全区域への移動経路・隊員配置・事案区域の整合性と、基準プレイで全事案を収束できること（クリア可能性）を検証し、満たさなければ派生シードで再生成する

### 評価（`generated/1.0.0`）

総合100点・5カテゴリの配点（安全管理30・初動対応25・指揮統制20・情報管理15・事態収束10）は共通です。

| カテゴリ | 評価項目 |
| --- | --- |
| 安全管理 | S1 避難開始・S2 警備員の安全確保・S3 地震時の安全確保（揺れの間の待機を評価）・S4 煙曝露 |
| 初動対応 | F1 通報区域への派遣・F2 119番（火災・救急）・F3 隊員配置（最寄り隊員による現着） |
| 指揮統制 | C1 役割分担・C2 優先順位・C3 指示の一貫性・C4 待機の妥当性 |
| 情報管理 | I1 未確認情報の現場確認・I2 新しい情報への対応・I3 地震後の安全確認 |
| 事態収束 | R1 事案の収束・R2 傷病者への救護 |

- 判断の時間は、その時点で入手できた情報（発報・内線通報・隊員の報告）から計測し、後で誤報・取り違えと判明した情報に基づく妥当な行動は減点しない
- **適応型（Easy〜Hard）**：時間基準を難易度の余裕と同時進行の事案数で調整し、発生した事案に該当する項目だけを評価
- **ハイブリッド型（Expert）**：安全管理と重大な安全違反は共通の厳格な基準（調整なし）、それ以外は状況に応じて調整
- 重大な安全違反（V1 退避判断後の進入・V2 避難措置の遅れ・V3 119番（火災）の遅れ・V4 揺れの最中の移動指示・V5 傷病者対応の遅れ）があれば、全難易度でランク上限 C
- 判断効率・安全性は補助指標として表示（総合得点には含まない）
- 履歴には難易度・シード・施設規模・評価ルールのバージョンを保存し、得点は同じシナリオ・同じ難易度どうしでのみ比較する

### 訓練結果画面（AAR）

「総合評価」「改善点」「詳細ログ」の3タブ構成（シナリオ01も共通）。評価根拠のイベント番号を押すと、詳細ログの該当行へ移動して強調表示します。

## v0.4：モバイル指揮UI（ランダム生成シナリオ）

iPhone での「モニター → 指示 → ログ」の画面切替を減らすため、ランダム生成シナリオのモニターに次を追加しました（シナリオ01の画面は従来どおり）。

- **マップ直接指示**：区域をタップすると指示シート（iPhone はボトムシート、iPad・PC は中央パネル）が開き、「区域 → 隊員 → 任務 → 送信」で指示できる。隊員ごとに現在地・現在の任務・到着予想時間を表示し、任務中の隊員への指示は上書きの確認を挟む。送信後はモニターに戻る。従来の指示画面もそのまま使える
- **タスクボード**：モニター上部の折りたたみ式（iPhone は最上位のタスク1行から開始）。把握済みの状況ごとに区域・内容・担当隊員・状態（未着手／対応中／待機／完了）を表示し、報告・指示・事案の収束で自動更新。タップでその区域の指示シートを開く。優先度（高・中・低）の変更と「完了」（手動）はボードの並び・表示の整理のみ
- **簡易通知**：新しい発報・通報・確認報告・危険の報告を緊急通知として短時間表示（タップで閉じる・ログへ移動）

**情報の公平性**：タスクと通知は、受信盤・内線・隊員の報告・自分の指示などプレイヤーが得た情報だけから作ります。未発見の事案、誤報かどうか、傷病者の実際の区域、将来の事案は表示せず、内容は状況の説明に留めて手順（正解）は示しません。並び順は目安で、AAR の評価基準とは無関係です。タスクボードの操作はイベント履歴に記録されないため、評価・採点結果は v0.3 と同じです。

## 公開（GitHub Pages）

`main` へのマージ（push）で GitHub Actions（`.github/workflows/deploy-pages.yml`）がテスト → ビルド → GitHub Pages へのデプロイを自動実行します。プルリクエストではテストとビルドのみ実行し、公開はしません。

- 公開 URL：https://f48ksf5hgf-art.github.io/NS-SIM/
- 公開されるのは `dist/`（ビルド済みの HTML / JS / CSS / アイコン）のみです。ソースマップは出力しません。ゲーム内データはすべて架空のものです
- Vite の `base` は本番ビルド時に `/NS-SIM/`。ルートで配信するホスティングでは `BASE_PATH=/ npm run build` でビルドします

### 初回のみ必要な設定

1. リポジトリの **Settings → Pages → Build and deployment → Source** を **GitHub Actions** にする
2. **Actions** タブで「Deploy to GitHub Pages」を **Run workflow**（または `main` へ push）

> GitHub Free プランでは、非公開（private）リポジトリで GitHub Pages を使えません。リポジトリを公開（public）にするか、GitHub Pro 以上にするか、Cloudflare Pages などの代替ホスティングを使ってください。なお GitHub Pro でも、公開されたサイト自体は URL を知っていれば誰でも閲覧できます。

### iPad / iPhone のホーム画面に追加

Safari で公開 URL を開き、共有ボタン →「ホーム画面に追加」で、アプリのように全画面で起動できます。

## 開発

```bash
npm install
npm run dev      # 開発サーバー（--host を付けると同一ネットワークの iPad / iPhone から確認可能）
npm test         # Vitest によるテスト
npm run build    # 型チェック + 本番ビルド（dist/）
```
